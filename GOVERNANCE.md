# Governance / Gouvernance

## Français
DN1-LAB est actuellement un dépôt de recherche maintenu par son propriétaire. Il ne revendique ni comité de gouvernance, ni organisation formelle, ni processus de vote collectif.

### Décisions
- Les changements de code sont proposés par Pull Request.
- La validation technique repose sur les tests reproductibles, les mesures, la revue du code et la traçabilité des sources.
- Les changements incompatibles, les IDs de machines et les nouvelles dépendances doivent être documentés.
- Une preuve hôte ne peut pas être transformée en affirmation de compatibilité matérielle.
- Les mainteneurs peuvent demander des tests, refuser une modification non vérifiable ou corriger la documentation pour refléter les limites constatées.

### Propositions de machines
Une nouvelle machine doit documenter son objectif sonore, ses différences par rapport au catalogue, son API, ses paramètres, son état par voix, ses ressources, sa licence, sa provenance, les antériorités pertinentes et ses critères de validation. Les IDs restent provisoires jusqu'au contrôle du build combiné.

### Conflits et conduite
Les désaccords techniques doivent rester argumentés et respectueux. Voir le [Code of Conduct](CODE_OF_CONDUCT.md).

## English
DN1-LAB is currently a research repository maintained by its owner. It does not claim to have a governance committee, formal organization or collective voting process.

### Decisions
- Code changes are proposed through Pull Requests.
- Technical validation relies on reproducible tests, measurements, code review and source traceability.
- Breaking changes, machine IDs and new dependencies must be documented.
- Host evidence must not be turned into a claim of hardware compatibility.
- Maintainers may request tests, reject unverifiable changes or correct documentation to reflect observed limitations.

### Machine proposals
A new machine must document its sonic goal, differences from the catalogue, API, controls, per-voice state, resources, license, provenance, relevant prior art and acceptance criteria. IDs remain provisional until the combined build is checked.

### Disagreements and conduct
Technical disagreement should remain reasoned and respectful. See the [Code of Conduct](CODE_OF_CONDUCT.md).
